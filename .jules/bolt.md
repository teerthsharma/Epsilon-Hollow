## 2024-05-18 - Zustand Full Store Subscription Anti-Pattern
**Learning:** Found a critical anti-pattern in the React+Zustand integration in `App.tsx` where the root application component destructured the entire Zustand store (`const { a, b } = useStore()`). Since `useStore()` without selectors subscribes the component to *all* state changes, any update to any unrelated store variable would trigger a re-render of the entire `App` component and all of its descendants, causing severe layout thrashing and performance degradation on high-frequency state updates (like log polling or telemetry).
**Action:** When using Zustand, always extract individual variables using specific selectors (e.g., `const a = useStore(s => s.a)`), or use `useShallow` for multiple variables, to tightly scope component reactivity only to the specific slice of state it actually requires.
